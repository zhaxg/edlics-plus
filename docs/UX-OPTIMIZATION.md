# UX 优化清单（对标 Cockpit）

> 现状：功能基本齐（指标/systemd/网络/用户/定时/容器/进程），但所有系统面板都塞进 IDE 的
> **窄侧栏**里（~260px），交互反馈弱、无路由、无空/错/载状态，多处长列表硬塞。
> 目标：把 Edlics 从「带后台面板的编辑器」升级为「Cockpit 式的分页控制台」，同时保留 IDE 能力。

## 进度

- ✅ **P0.1 单列全宽页 + 页面合并 + hash 路由**（commit `28b473f`）：Console 页面移入
  `#consoleArea` 全宽单列；IDE 视图保留侧栏；`#/services` 等可刷新/分享/前进后退；
  **Users + Scheduled 合并为 Access 页**（账号区 + Scheduled 区一页两段）；Dashboard 卡片化、图表加高。
- ✅ **P0.2 对话框 + P0.4 反馈**（commit `f34a55d`）：可堆叠/可关闭 toast（错误不自动消失）；
  `confirmDialog`(危险色/自定义按钮) / `promptDialog` / `choiceDialog`；进程发信号、TOTP 停用
  改用对话框（**已无 `window.prompt`**）；服务操作 busy 态；多处 `Loading…` 换成 spinner。
- ⏳ 待做：P0.3 空/错态统一、P0.5 表格化与虚拟滚动；P1（Dashboard 下钻、日志抽屉、徽标、
  命令面板、告警）；P2（响应式/A11y/组件收敛/性能）。

## 0. 与 Cockpit 的核心差距（一句话）| 维度 | Cockpit | 现状 | 差距 |
|---|---|---|---|
| 信息架构 | 左侧导航栏 + **全宽页面**（Overview/Logs/Storage/Networking/Accounts/Services/Terminal…） | 全部挤在一个窄侧栏 | ★★★ |
| 路由 | 每页有 URL，可刷新/分享/前进后退 | 无路由，刷新回 Explorer | ★★★ |
| 概览 | 顶部 KPI 卡片 + sparkline，可点进详情 | 84px 小图挤在侧栏 | ★★★ |
| 日志 | 独立日志页：级别过滤/搜索/跟随/下载 | 侧栏内联 `<pre>` | ★★ |
| 反馈 | 内联 spinner、进度、明确的成功/失败、非阻塞 | `window.prompt` / toast 一闪而过 | ★★★ |
| 列表 | 搜索、排序、状态徽标、批量/行操作 | 部分有，样式不一 | ★★ |
| 告警 | 系统事件通知中心 | 无 | ★★ |
| 响应式/可访问 | 键盘可达、焦点可见、ARIA | 未系统处理 | ★★ |

## P0 — 结构性改造（UX 提升最大，先做）

### 布局原则（修订）
**不要每个页面都做成左右分栏。** 现状的问题是：打开系统面板时内容挤在窄侧栏，而右侧编辑区空着，
白白浪费主区。修订后的原则：

- **默认「单列全宽页」**：Console 页面（Overview/Services/Network/Users/Scheduled/Containers/Processes）
  直接铺满主内容区，**一列堆叠卡片/分区**，不再强制「左列表 + 右内容」。
- **图标活动栏只当导航**：它是一条窄图标轨（不是内容分栏），点哪个图标就切换整页内容。
- **只有在「选中了某一条」时才出现主从分栏**，并且是**按需出现**、可关闭：
  - 服务页：默认全宽列表；点某个服务 → 右侧抽屉/详情（日志、操作），再点关闭即回到全宽。
  - 进程页同理（详情抽屉展示 cmdline/环境/打开文件）。
- **能合就合**：把功能相近的窄面板合并成一页的多个 section，减少导航项与来回切换。

### 合并后的页面结构（8 个窄面板 → 5 个全宽页）

| 合并后的页 | 内容（原先拆散的 section） | 布局 |
|---|---|---|
| **Dashboard** | 指标 KPI+图（原 Overview） + 系统信息 + Top 进程 + 告警 | 单列卡片网格 |
| **Services** | 服务列表（原 Services） + journal 日志（原内联在行里） + systemd timers（原 Scheduled 的一半） | 全宽列表 + 按需详情抽屉 |
| **Network** | Ifaces / Routes / Sockets / FW（原 Network 四页签） | 单列 + 页内页签 |
| **Storage** | 各挂载点占用 + 磁盘吞吐（新增，补 Cockpit 的 Storage） | 单列卡片 |
| **Access** | 用户/组/会话（原 Users） + crontab（原 Scheduled） | 页内页签（Users/Groups/Sessions/Cron） |
| **Containers** | 容器 + compose（原 Containers） + 日志 | 全宽列表 + 按需详情抽屉 |
| **Processes** | 进程表（原 Processes） | 全宽表 + 按需详情抽屉 |

> 说明：`Dashboard` 里的 Top 进程只是**摘要**，点进去才到 Processes 全页——避免同一份数据做成两个页面。
> `Services` 吸收 `Scheduled` 的 timers（都是 systemd 单元），`Access` 吸收 crontab（都是账号/计划）。

### P0.1 单列全宽页 + 轻量路由（对标 Cockpit 页面）
- [ ] **IDE 视图保留侧栏**（Explorer/Search/Git 是「列表 + 编辑器」天然分栏，维持现状）
- [ ] **Console 视图改为单列全宽页**：内容渲染进主区（与 `#editorArea` 同级的新容器），
      **不再挤进侧栏**；活动栏图标 = 页面切换器
- [ ] 合并页面（见上表），导航项从 8 个减到 ~5 个，减少切换成本
- [ ] **主从分栏按需**：只有选中条目时才展开右侧详情抽屉（含日志/操作），Esc 或关闭即回到全宽
- [ ] **hash 路由** `#/dashboard`、`#/services`、`#/services/nginx.service`、`#/processes`…：
  - 刷新/前进后退/直接分享链接都回到同一页（当前刷新丢失视图）
  - `state.currentView` 与 `location.hash` 双向同步（`hashchange` 监听）
- [ ] 记住上次所在页（localStorage），下次打开直达
- [ ] 导航项显示**徽标**（Services = failed 单元数、Containers = 运行数）


### P0.2 干掉 `window.prompt / window.confirm` 反模式
- [ ] 进程发信号：把 `window.prompt('TERM/KILL…')` 换成**下拉菜单 + 确认对话框**（危险信号红色）
- [ ] TOTP 停用：把 `prompt('输入验证码')` 换成带输入框的对话框（复用 `api.mjs` 的 dialog）
- [ ] 统一走一个 `Dialog` 组件：普通确认 / 危险确认（红按钮）/ 带输入 / 带进度
- [ ] 所有破坏性操作：**危险色按钮 + 明确对象名**（不是「确定」而是「停止 nginx.service」）

### P0.3 三态齐全：加载 / 空 / 错
- [ ] 每个面板统一三态：**骨架屏/Spinner**（加载中）、**友好空态**（含「为何为空 + 建议」）、
      **错误态**（错误信息 + **重试按钮**）
- [ ] 现状多处是裸 `Loading…` / 直接空白；`overview/ services/ network…` 逐一替换
- [ ] 请求失败不再静默 `catch(()=>{})`——至少 toast + 可重试

### P0.4 反馈与操作态
- [ ] 按钮点下立即进入 **loading（禁用 + spinner）**，完成后 **明确成功/失败**（不只 toast）
- [ ] 危险操作二次确认（已部分有），失败要**保留对话框**并显示原因（现在直接关掉）
- [ ] Toast 升级：**可堆叠、可手动关闭**、错误**不自动消失**（当前 2.5s 一闪，容易漏）
- [ ] 行内操作结果**就地反映**（如服务启停后该行状态点变色并刷新，而非干等）

### P0.5 全宽列表排版（表头/对齐/密度）
- [ ] 服务/进程/用户/容器/任务：统一成**真正表格**（固定列宽、表头粘顶、数值右对齐、等宽字体）
- [ ] 列宽不随内容跳动；长文本省略 + tooltip；行 hover 高亮
- [ ] 长列表**虚拟滚动或分页**（services 188、processes 300+，现在全渲染）
- [ ] 每页统一**顶部工具条**：搜索框 + 排序 + 刷新 +（可选）筛选 chips

## P1 — 体验升级（对标 Cockpit 的成熟感）

### P1.1 Dashboard 升级为真正的仪表盘
- [ ] 顶部 **KPI 卡片**：CPU、内存、磁盘、网络 —— 大数字 + 迷你 sparkline + 趋势色
- [ ] 点卡片**下钻**到详情页（CPU → Processes；磁盘 → Storage；网络 → Network）
- [ ] 主图表**加高**（≥ 240px），支持时间范围切换、图例、hover 十字线读数
- [ ] 卡片网格自适应列数（宽屏多列、窄屏单列），不是固定窄栏
- [ ] 磁盘/挂载用量视图（当前只有 `/proc/diskstats` 吞吐，缺**各分区占用**）→ 见 Storage 页

### P1.2 日志视图（Services / Containers 详情抽屉，可全屏）
- [ ] 选中服务/容器时才展开的**详情抽屉**里给全宽日志：**级别过滤**、**关键字搜索**、
      **跟随(follow)开关**、**下载**、**全屏**
- [ ] 行级着色 + 时间戳；自动滚到底（用户上滚时暂停跟随）
- [ ] 可从 Dashboard 告警/服务行**一键跳转**（URL 带 `#/services/nginx.service#logs`）

### P1.3 导航徽标与实时性
- [ ] Services 徽标=failed 数；Containers=运行/退出；Processes=总进程数或高负载提示
- [ ] 数据页显示 **live 指示**（脉冲点 + 最后更新时间），刷新节奏可感知
- [ ] 统一**自动刷新**（可开关）：Overview/Processes 默认开，其余按需

### P1.4 全局搜索 / 命令面板（Ctrl+K）
- [ ] `Ctrl+K` 命令面板：跳页、启动/停止服务、打开容器日志、执行预设动作
- [ ] 侧栏搜索与全文搜索已有，补**跨系统实体**的快速定位（服务/容器/进程）
- [ ] `Ctrl+/` 快捷键帮助浮层（现在快捷键只散落在文档里）

### P1.5 通知与告警中心
- [ ] 顶部铃铛 + 未读计数：服务失败、磁盘将满、负载过高等事件
- [ ] 阈值告警（CPU/内存/磁盘/负载）产生**持久通知**（落 SQLite，刷新不丢）
- [ ] 可选 webhook/邮件外发（Phase 9）

## P2 — 精细化与可访问性

### P2.1 响应式
- [ ] 窄屏（< 900px）：导航折叠为图标条/抽屉，表格横向滚动或切换卡片式
- [ ] 移动端至少可读可操作（查看指标/日志、启停服务）

### P2.2 可访问性（A11y）
- [ ] 全键盘可达：Tab 顺序、焦点可见（`focus-visible` 描边）、Esc 关闭弹层
- [ ] 对话框：`role="dialog"`、`aria-modal`、初始聚焦、焦点陷阱
- [ ] 状态点/徽标：不只靠颜色，附图标或文本（色盲友好）
- [ ] Toast/告警容器 `aria-live="polite"`

### P2.3 组件与视觉一致性
- [ ] 抽一套组件 CSS：`Card / Table / Badge / Button / Tabs / EmptyState / Spinner / Dialog / Toast / Tooltip`
- [ ] 统一间距/圆角/字号刻度；明暗主题全组件复核（当前部分内联样式绕过变量）
- [ ] 去掉散落的**内联 style**（index.html 里大量），收敛到类

### P2.4 性能/手感微优化
- [ ] 搜索/过滤 **debounce**（当前每次按键都打后端）
- [ ] 面板切换加轻量过渡；避免布局跳动
- [ ] 大响应（日志/进程）**分页或上限 + 加载更多**
- [ ] 骨架屏替代跳动的「Loading…」

### P2.5 会话与安全体验
- [ ] 会话到期**友好提示**并保留当前页（现在会被弹回登录、丢上下文）
- [ ] 首次启用 2FA 的引导（二维码/复制按钮，而不只是丢一串 secret）
- [ ] `--readonly` / 无 `--admin-write` 时，**隐藏或置灰**写操作并说明原因

## 建议的执行顺序（每步都可独立验收）

1. **P0.1 单列全宽页 + 页面合并 + hash 路由**（一次结构性重排，收益最大）
2. **P0.3 + P0.4 三态与反馈**（去掉「点了没反应/报了看不到」的挫败感）
3. **P0.2 对话框组件**（消灭 prompt/confirm）
4. **P0.5 列表统一成表格**（对齐、粘顶、虚拟滚动）
5. **P1.1 Overview 仪表盘 + P1.2 日志页**
6. **P1.3 徽标/实时 + P1.4 命令面板 + P1.5 告警**
7. **P2 响应式 / A11y / 组件收敛 / 性能**

## 验收基线（对标 Cockpit 自检）

- [ ] 任意系统页可**直接链接**并刷新还原
- [ ] 任何操作员都能在 **3 秒内**看清「点了什么、成功了没」
- [ ] 任何列表都有**搜索 + 排序 + 三态**
- [ ] 不存在 `window.prompt / alert`；破坏性操作有明确对象名的确认
- [ ] 键盘可完成：切页、搜索、执行一次服务启停、关闭弹层
- [ ] 窄屏下不横向溢出、不错位
